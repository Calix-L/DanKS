# 二次开发指南

先按 README 启动，用示例机器人完整玩一局，再按下面的入口修改。
无需获取任何私有模型、服务器配置或推理环境。

## 目录与边界

```text
web/           浏览器页面、视觉素材与交互
backend/       房间状态、权限、HTTP/WebSocket 与展示数据
rules/engine/  洗牌发牌、牌型、合法动作与规则结算
arranger/      完整理牌源码与四种组合优先方式
scripts/       本地理牌模块源码编译入口，不含业务部署脚本
workers/       每桌独立裁判进程、示例选牌、公开观察转换
integrations/  与外部 AI 通信的通用 HTTP 接口
docs/          开发说明与两侧接口协议
```

依赖方向是：网页调用房间 API；房间通过 NDJSON 调用裁判 worker；worker 使用
规则引擎。配置 AI 接口后，worker 将自己可见的牌局信息交给 `integrations/ai.py`。
浏览器不接触外部 AI 地址，也不接触其他玩家的手牌。

## 我要改哪里？

| 改动 | 入口 | 验证 |
| --- | --- | --- |
| 牌桌布局、按钮和颜色 | `web/play.html`、`web/play.css` | 浏览器桌面/手机横屏检查；中英文字不遮挡 |
| 出牌、选牌、断线恢复交互 | `web/play.js`、`web/frontend/hand-interactions.mjs`、`room-api.mjs`、`solo-session.mjs` | 点击/拖选/键盘操作、刷新恢复与网络断连检查 |
| 牌面/头像 | `web/assets/`、`web/frontend/card-ui.mjs`；新文件需加入静态资源白名单 | Network 素材加载与重复实体牌身份检查 |
| 房间、准备、鉴权和结算推进 | `backend/human_tables.py` | API 状态/版本、完整结算与玩家私有视图检查 |
| 增加或修改 HTTP 路由 | `backend/solo_app.py`、`backend/human_table_models.py` | 按 `GAME_API.md` 请求，检查失败码并更新文档 |
| 牌型识别/大小比较 | `rules/engine/python_rules.py` | 固定牌例逐项核对；本地工具检查 108 张实体牌守恒 |
| 发牌、轮转、规则状态推进 | `rules/engine/table.py`、`types.py` | 固定种子完整对局、出完顺序和下一局检查 |
| 改示例机器人 | `workers/table_worker.py` 中的 `choose_rule_action` | 完整对局；每步选牌属于当前合法动作 |
| 接自有 AI | `integrations/ai.py`；观察转换在 `workers/http_policy.py` | 按 `AI_INTERFACE.md` 用本地服务检查请求与失败恢复 |
| 改理牌展示/算法 | `backend/presentation.py`、`arranger/common/` | 编译后核对四种模式、候选切换、牌张身份与守恒 |

`human_tables.py` 保留经过回归的房间生命周期实现，不为目录整洁而重写游戏流程。
其中部分通用回放/协议结构仍为历史兼容代码；对外应用只开放掼蛋单人模式。

## 一次改动的工作顺序

此公开包不附带开发侧测试源码；开发侧历史回归仍单独保留。以下手动检查不能
代替自己的自动化回归，尤其是规则修改的固定种子和牌数守恒验证。

1. 先在自己的验证工具中记录能复现目标行为的失败用例。
2. 只改上表中对应的模块，不把规则判断散落到网页里。
3. 完成下文的浏览器/API/完整对局清单，记录输入、返回状态和预期结果。
4. `python run.py` 后打开 `/solo`。前端静态文件无需打包工具；后端改动后重启。
5. 如果改变请求字段或动作含义，同步更新接口文档与自己的调用方回归。

修改 Go 理牌源码并审查后，运行
`python scripts/build_arranger.py --refresh-manifest` 显式更新源码指纹并重新编译。
普通编译会核验已有指纹，不会自动接受源码变化。`source_fingerprint` 对应当前公开
源码（统一 LF 换行）；`algorithm_source_sha` 是原算法来源标识，不是修改后的文件哈希。
重新编译后逐项检查四种理牌模式与候选切换，再完整玩一局并核对牌张守恒。

前端 HTML/模块带缓存版本号；发布自己的改动时，要同步更新被改文件的引用
版本号。不要直接双击 HTML：页面需要同源 API/WebSocket，应从本地服务访问。

## 手动验收清单

1. 按 README 编译与启动，执行 `curl -fsS http://127.0.0.1:8000/api/health`。
   从服务打开 `/solo`，检查浏览器 Console/Network 无缺失模块或素材，HTTP 与
   WebSocket 状态能更新。桌面与手机横屏分别检查中英文、选牌、拖选、键盘操作、
   历史记录、按钮 busy/disabled、对话框焦点恢复与减少动态效果偏好。
2. 创建、准备并完整玩多局机器人对战，覆盖出牌/过牌、清墩、出完顺序、结算与
   下一局。规则改动使用自己的本地工具记录固定种子/发牌与裁判状态：每步手牌加
   已出牌始终为 108 张实体牌，机器人动作必须来自当前合法列表。逐项核对自然
   A 高于 2、同点不能压过、级牌提升、王、红桃配牌及级别 10/T/t；界面正常不代表
   这些规则已被充分验证。
3. 四种理牌模式及重复点击候选切换均检查实体牌 ID 与张数不变。覆盖 13 个级别、
   重复牌、红桃配牌、王、空手牌和炸弹/同花顺优先冲突牌例；理牌不得推进裁判。
4. 按 [GAME_API](GAME_API.md) 的请求体，用浏览器 Network 或本地 HTTP 客户端
   检查缺失/错误 token、旧版本、错误 decision ID、越界 action index 的拒绝，
   确认失败不改手牌与回合。检查 HTTP/WebSocket 私有视图只含本人手牌，其他座位
   只公开张数和已出牌。用随机私密 user_id 恢复座位后，旧 HTTP token 应为 401、
   旧 socket 关闭 4401 且不再交付排队私有视图；不存在房间为 404/4404。
5. 浏览器切换离线/在线，检查普通断线有上限退避；鉴权撤销/缺失房间停止自动
   重连并回入口。离开房间时故意延迟 ready/arrange/retry 响应，确认晚到返回不能
   恢复旧房间或覆盖新房间，恢复期间不泄露旧手牌。
6. 用遵循 [AI_INTERFACE](AI_INTERFACE.md) 的独立本地 HTTP 服务检查当前行动者
   可见请求；强制超时、畸形返回、request ID 不符与非法索引。应在裁判提交前暂停，
   不自动改用机器人。恢复端点后用最新版本显式重试，同一 decision 与合法列表应
   保持；未授权重试被拒、旧版本冲突为 409。非可重试 engine_failure 只能返回
   入口；公开错误不含上游地址、堆栈或其他玩家手牌。

## 房间与出牌的约束

- 玩家身份、座位、版本号和合法动作由后端决定，前端不能自行推进牌局。
- 浏览器稳定 `user_id` 可用于恢复原座位，应使用随机不可预测值并当作恢复凭据
  保密，不要改成公开昵称或固定账号字符串；详见 `GAME_API.md`。
- `action_index` 只对当前 decision 有效；出牌需带版本与 decision ID。
- 其他玩家只能公开剩余张数和已出的牌，不能发送隐藏手牌给浏览器或 AI。
- 同点的两副牌必须按张数处理，不能用集合去重；修改后必须保留 108 张牌守恒。
- 房间在内存中，运行日志在 `data/`，不应提交到代码库。

## 不包含的实现

此包没有线上模型、网络、检索/特征、权重、推理加速、激活系统及 AI 服务部署。
完整手牌理牌模块已经包含；它只整理可见手牌，不承担 AI 推理或训练检索。
新增 AI 能力请按公开接口接入自己的服务，不需要也不应往这里加入私有部署配置。

## 发布自己的版本前

维护者已确认本项目源码及素材的自有来源；二开时仍需保留依赖许可和商标说明。
不要把运行产生的 `data/`、`runtime/`、`.env`、凭据或模型文件打进源码包。
